## Context

当前工作区已采用全宽 TopBar、桌面 Sider 和小屏 Drawer。后续提交将桌面菜单转换为静态 `Menu group`，并使用 Ant Design Sider 底部默认 trigger，导致父菜单不能展开、折叠入口与参考图不一致、折叠状态也未持久化。现有 `ui-layout-contract.test.mjs` 还保留部分旧页面结构断言，使最新 main 的基线测试失败。

## Goals / Non-Goals

**Goals:**

- 在不改变路由和业务页面的前提下实现 Ant Design Pro 风格的层级侧栏。
- 桌面端提供默认展开、220/64px 切换、边界圆形触发器和状态持久化。
- 当前路由自动选中子项并展开所属父菜单。
- 小于 992px 时继续使用完整抽屉菜单。
- 恢复 Web 布局契约的干净基线并覆盖新行为。

**Non-Goals:**

- 不复制参考图中的第三方品牌、示例页面和右侧设置入口。
- 不改变页面内容布局、API、权限和业务数据。
- 不引入新的菜单或状态管理依赖。

## Decisions

### 1. MENU_ITEMS 直接作为 Ant Design 子菜单树

`menu.tsx` 保持唯一导航来源，并补回仪表台一级项。`SideNav` 不再把父节点转换成静态 group，而是将 `MENU_ITEMS` 映射为带 `children` 的 `MenuProps['items']`。这样展开、折叠浮层、键盘交互和选中态均由 Ant Design Menu 提供。

替代方案是保留 group 并自行渲染展开区域，但会重复实现 Menu 已有的无障碍和浮层行为，因此不采用。

### 2. SideNav 自己拥有桌面折叠和子菜单展开状态

桌面折叠初始值从 `ledger:sidebar-collapsed` 读取；无记录时为 `false`。切换时同步写入 localStorage。子菜单 `openKeys` 根据当前路径初始化并在路由变化时补充所属父键，同时允许用户手动控制展开集合。

抽屉模式不读取桌面折叠状态，始终渲染完整导航文字，避免桌面偏好污染小屏体验。

### 3. 禁用 Sider 默认 trigger，使用边界按钮

Sider 设置 `trigger={null}`，内部渲染 `sidebar-collapse-trigger` 真按钮，绝对定位在右边界顶部。展开/折叠分别使用左右箭头，按钮拥有 `aria-label`。CSS 负责尺寸、边框、阴影、主题和过渡。

相比底部 trigger，该方案与参考图的位置和可发现性一致，也不会占用菜单底部空间。

### 4. 基线契约按当前页面结构校正

保留响应式摘要、行操作和布局壳契约；将已经被后续页面布局提交移除的 `PageHeader`/`PageToolbar` 字符串断言替换为当前可观察结构断言。移动菜单按钮补充 `aria-label="打开导航"`，这是实现缺失而非测试过时。

## Risks / Trade-offs

- **[风险] 折叠状态与父菜单展开状态互相影响。** → 折叠仅控制 Sider 宽度，`openKeys` 独立保存于组件状态，展开后恢复当前路由父菜单。
- **[风险] 边界按钮覆盖内容。** → 按钮中心固定在侧栏边界，主内容保留现有内边距，并在 992px 以下完全移除按钮。
- **[风险] 暗色主题对比不足。** → 所有背景、边框和文字使用现有 CSS token，仅阴影使用透明中性色。
- **[取舍] 仅持久化侧栏宽度，不持久化父菜单 openKeys。** → 当前路由始终可恢复正确父菜单，避免保存过期导航状态。

## Migration Plan

1. 先修复契约基线并确认除新功能断言外测试通过。
2. 更新菜单树、SideNav 状态和触发器。
3. 添加主题与响应式 CSS。
4. 运行测试、构建、lint 和多视口无头浏览器验收。
5. 如需回滚，恢复 SideNav 的静态 group 与默认 trigger；无数据迁移需求。
